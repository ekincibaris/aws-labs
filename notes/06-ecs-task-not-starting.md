We have an issue read-db-password policy to the task role by mistake, while the execution role only had AmazonECSTaskExecutionRolePolicy (which covers ECR and logs, not SSM). Because ECS uses the execution role to pull secrets before the container even starts, the task was crashing before the app could run. I moved that ssm:GetParameters policy over to the execution role in iam.tf, redeployed, and the task finally hit RUNNING and logs showed up Lesson learned: secrets in the task definition belong on the execution role, while app SDK calls go on the task role—and next time I'll run aws iam simulate-principal-policy before deploying to catch this upfront.
