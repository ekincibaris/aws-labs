When the worker fleet failed to scale out despite CPU sitting at 50% and the CloudWatch alarm firing, we saw that the Auto Scaling group remained stuck at 1 instance with no new scaling activities. Then we inspected the group with aws autoscaling describe-auto-scaling-groups and saw that the AlarmNotification process was suspended. So the ASG was ignoring the target tracking alarm notifications and never increasing its desired capacity. We removed suspended_processes = ["AlarmNotification"] from asg.tf, which fixed the issue. To prevent this, an AWS Config rule should flag any ASG with suspended processes and an EventBridge alert should monitor SuspendProcesses API calls.
